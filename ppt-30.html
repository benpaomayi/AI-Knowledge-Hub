Step 1: 数据准备

数据决定了上限，模型只是在逼近这个上限

📥 数据收集与清洗

  • 收集足够的标注数据
  • 处理缺失值、异常值
  • 检查标签是否正确（错误标签很致命！）
  • 去重、统一格式

✂️ 数据集划分

  • Train: 训练模型（70-80%）
  • Val: 调参选模型（10-15%）
  • Test: 最终评估（10-15%）
  • 划分前先shuffle！
  • 注意类别不平衡问题

🔧 预处理与增强

  • 标准化/归一化
  • 数据增强（CV翻转/裁剪等）
  • 转Tensor、构建DataLoader
  • 注意：train/val预处理一致

⚠️ 数据泄露是大忌！

验证集/测试集的信息绝对不能泄露到训练过程中。比如用全量数据做标准化（应该只用train的mean/std）、特征选择用到了标签、数据增强错误应用到val/test——这些都会让你得到虚高的分数，上线就崩。

Step 2: 选择模型架构

从简单开始，不要一上来就用最复杂的模型

🎯 原则：从简单基线开始

永远从最简单的模型开始跑通整个pipeline，建立baseline。不要一上来就堆Transformer、ResNet。先用小模型（比如1-2层MLP）快速验证思路，再逐步加深加大。

任务类型 首选基线模型 进阶模型
表格数据分类/回归 MLP（2-3层全连接） XGBoost/LightGBM（其实树模型更强）
图像分类 简单CNN（LeNet风格） ResNet、EfficientNet、ViT（预训练微调）
文本分类 Embedding + LSTM/TextCNN BERT/RoBERTa等预训练模型微调
目标检测 YOLOv8（直接用） 根据场景选择，用开源SOTA

💡 优先用预训练模型

现在不是2012年了！CV用torchvision的预训练ResNet，NLP用HuggingFace的BERT，在自己数据上微调，比从头训效果好10倍，还快得多。

Step 3 & 4: 损失函数 & 优化器

根据任务选损失，优化器默认Adam

📉 损失函数选择

回归任务：

  • MSELoss——均方误差，默认首选
  • HuberLoss(SmoothL1)——对异常值鲁棒
  • MAELoss——平均绝对误差

分类任务：

  • CrossEntropyLoss——多分类默认（内含Softmax）
  • BCEWithLogitsLoss——多标签/二分类

⚡ 优化器选择

✅ 默认推荐：Adam / AdamW

自适应学习率，收敛快，调参少，对初始化不敏感。90%的场景用Adam就够了。

⚡ 追求极致：SGD + Momentum

需要仔细调学习率，收敛慢但最终可能到更好的最优点。论文刷点常用。

其他：RMSprop、Adagrad等历史产物，现在很少用了。

Step 5: 超参数设置——学习率最重要

学习率是最重要的超参数，没有之一

🔴 学习率 (Learning Rate)——最重要！

常用尝试范围：1e-2, 1e-3, 1e-4, 5e-4, 1e-5

  • Adam默认1e-3是不错的起点
  • 微调预训练模型用更小的lr（1e-4或1e-5）
  • 太大：loss震荡/NaN；太小：收敛极慢
  • 推荐用学习率调度器（Cosine/StepLR）

📦 Batch Size

  • 显存允许的话越大越好（32, 64, 128...）
  • batch size大，学习率也可以调大（线性缩放规则）
  • batch太小（≤8）效果差，BN不准
  • 显存不够：梯度累积

🔢 Epoch数

  • 一开始先设10-20epoch看趋势
  • 用Early Stopping自动决定何时停
  • 不够就加，太多浪费时间还可能过拟合
  • 微调预训练模型epoch少（3-10）

Step 6: 训练循环核心代码

训练循环的标准pipeline

def train_one_epoch(model, loader, criterion, optimizer, device):
  model.train()
  total_loss = 0
  correct = 0
  for x, y in loader:
    x, y = x.to(device), y.to(device)
    optimizer.zero_grad() # ① 梯度清零！
    logits = model(x) # ② 前向传播
    loss = criterion(logits, y) # ③ 计算loss
    loss.backward() # ④ 反向传播
    optimizer.step() # ⑤ 更新参数
    total_loss += loss.item() * x.size(0)
    correct += (logits.argmax(1) == y).sum().item()
  return total_loss / len(loader.dataset), correct / len(loader.dataset)

🚨 最常见bug：忘记zero_grad()

每轮迭代开始前必须调用optimizer.zero_grad()清空梯度，否则梯度会累积，结果完全错误。这是新手犯错率最高的地方之一！

验证循环与完整训练模板

每个epoch后必须在验证集上评估

def evaluate(model, loader, criterion, device):
  model.eval() # 🔴 切换到评估模式！
  total_loss = 0
  correct = 0
  with torch.no_grad(): # 不计算梯度，省显存加速
    for x, y in loader:
      x, y = x.to(device), y.to(device)
      logits = model(x)
      loss = criterion(logits, y)
      total_loss += loss.item() * x.size(0)
      correct += (logits.argmax(1) == y).sum().item()
  return total_loss / len(loader.dataset), correct / len(loader.dataset)

# 训练主循环
for epoch in range(num_epochs):
  train_loss, train_acc = train_one_epoch(...)

训练曲线诊断

训练出问题了？看曲线就知道是什么问题

✅ 理想曲线（训练正常）

train loss稳步下降，val loss也稳步下降然后趋于平稳，两者差距小。train acc和val acc都上升然后趋于平稳，接近。这说明模型正常训练，泛化良好。

📊 诊断口诀

看loss比看acc重要！loss是优化的直接目标，acc只是离散指标。训练时优先看loss曲线。

🔍 我们接下来看4种典型症状：

  • 1. train和val loss都不下降——学习率/模型容量/数据问题
  • 2. train loss下降但val loss上升——过拟合
  • 3. train loss下降很慢——学习率太小/初始化/梯度消失
  • 4. loss=NaN——梯度爆炸

症状1：loss不下降（loss stays high）

训练loss和验证loss都不降，模型什么都没学到

🔴 可能原因及解决方案：

原因1：学习率太大或太小 → 学习率太大：loss震荡甚至上升，尝试降低lr（除以10）
→ 学习率太小：loss几乎不动，尝试提高lr（乘以10）
💡 建议：先试lr=1e-3，不行再试1e-4和1e-2
原因2：模型容量不够 → 模型太简单，学不到数据中的模式
→ 解决方案：增加层数/增加隐藏维度/换更复杂的架构
原因3：数据/代码bug → 检查数据是否正确加载？标签对不对？
→ 有没有忘记zero_grad()？loss计算对不对？
→ 数据预处理是否正确？归一化做了吗？
→ Sanity Check：用极小数据集（10-100个样本）测试能不能过拟合

症状2：过拟合（train好val差）

train loss一直降，val loss先降后升——这是最常见的情况

🔴 典型表现

train loss接近0，train acc接近100%；val loss上升，val acc停滞甚至下降；两者gap越来越大。模型在死记硬背训练集。

✅ 解决方案（按优先级）：

  1. 加数据/数据增强——最有效！CV加翻转/裁剪，收集更多真实数据
  2. 加Weight Decay——优化器设置weight_decay=1e-4
  3. 加Dropout——MLP加p=0.5的Dropout层
  4. Early Stopping——val loss不提升就停，选best checkpoint
  5. 简化模型——减少层数/神经元，不要用太复杂的模型
  6. 标签平滑——分类任务加label_smoothing=0.1
  7. 加BatchNorm——BN也有正则化效果

症状3：收敛太慢/训练不动

loss在下降，但下降非常非常慢，训练几十epoch还没收敛

🟡 可能原因：

📉 学习率太小

lr过小导致每步更新太小，loss像蜗牛爬。

解决：把lr调大5-10倍试试。

⚠️ 初始化不好

权重初始化不合理导致梯度消失/饱和。

解决：用PyTorch默认的Kaiming/Xavier初始化，或用预训练模型。

📉 梯度消失

深层网络sigmoid/tanh导致梯度消失。

解决：用ReLU激活、加BatchNorm、用残差连接。

💡 其他可能

优化器选择（SGD比Adam收敛慢但可能更好）、没有做数据归一化、学习率没设对、网络太深但没有残差连接。

症状4：loss=NaN（最吓人的bug）

训练中loss突然变成nan，训练直接崩了

💥 NaN = 梯度爆炸或数值不稳定

loss=NaN 99%是梯度爆炸导致的——梯度变得太大，更新步长太大，参数越更新越离谱，越算越大，最终溢出变成NaN（Not a Number）。

🛠️ 解决方案（按优先级）：

  1. 降低学习率！——lr太大是NaN的第一大原因，除以10试试
  2. 梯度裁剪——torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
  3. 检查数据——数据里有没有NaN/inf？有没有除以0？标签对不对？
  4. 检查loss计算——CrossEntropy的target要是long类型；有没有log(0)？
  5. 降低权重初始化范围——初始化值太大
  6. 混合精度训练要注意——用GradScaler避免fp16溢出
# 加这行在loss.backward()之后、optimizer.step()之前
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)

超参数调优优先级

超参数这么多，先调哪个后调哪个？

🥇 优先级1：学习率 (lr) 影响最大！合适的lr和差的lr能差10倍以上效果。先试1e-3, 1e-4, 1e-2三个量级，找到loss下降最快的那个区间再细调。
🥈 优先级2：Batch Size 显存允许尽量大（32-256）。batch size大，训练更稳定，梯度更准，也可以用更大学习率。
🥉 优先级3：网络深度/宽度 从简单小网络开始，容量不够再加深加宽。先2层，不够再加到3-4层。
4. 优化器选择 默认AdamW/Adam就很好，不要在这上面浪费太多时间。
5. 正则化强度 Weight Decay(1e-4)、Dropout(0.3-0.5)、数据增强策略——在确定能过拟合之后再调。

💡 调参建议

一次只调一个参数！不要同时改lr、batch size、网络结构，否则你不知道是哪个改动起了作用。

第一步：Sanity Check！

在正式训练前，先做一个最重要的测试

🧪 Sanity Check（合理性检查）

取一个很小的数据集（比如10-100个样本，甚至1个batch），让模型在这个小数据集上训练，看能不能把loss降到接近0，准确率达到100%。

✅ 如果Sanity Check通过：

说明模型、loss计算、反向传播、优化器都是正常工作的。模型有能力记住数据，代码没有致命bug。然后再在全量数据上训练。

❌ 如果Sanity Check不通过：

连10个样本都记不住？100%是代码bug！别浪费时间在全量数据上训练了，先修bug。常见问题：

  • 忘记zero_grad()？
  • loss函数用错了？（分类用MSE？）
  • 数据/标签加载错了？
  • 模型输出维度不对？
  • 学习率设得太离谱？

⭐ 这是最高效的debug方法！

很多新手一上来就用全量数据训练，跑几个小时发现不对，浪费时间。先花2分钟做Sanity Check，能避免90%的无效训练。

学习率调度器 (Scheduler)

让学习率在训练中动态变化，收敛更好

📈 为什么需要scheduler？

训练初期用大lr快速收敛，后期用小lr精细调整到最优点。固定lr不是最优的。

常用scheduler：

  • CosineAnnealingLR——余弦退火，现在最流行，效果好
  • StepLR——每N个epoch乘gamma
  • ReduceLROnPlateau——val loss不下降就自动降lr
  • OneCycleLR——Super Convergence，先升后降

🔧 PyTorch代码示例

from torch.optim.lr_scheduler import CosineAnnealingLR

optimizer = torch.optim.AdamW(
  model.parameters(),
  lr=1e-3,
  weight_decay=1e-4
)
scheduler = CosineAnnealingLR(
  optimizer,
  T_max=num_epochs
)

# 训练循环中每个epoch后：
scheduler.step()

梯度裁剪 (Gradient Clipping)

防止梯度爆炸的简单有效技巧

📐 原理

在反向传播后、更新参数前，如果梯度的范数（大小）超过了阈值max_norm，就按比例把梯度缩放到max_norm，限制步长不要太大。这是RNN/LSTM训练的标配，现在大模型训练也常用。

# 训练循环中：
optimizer.zero_grad()
loss = criterion(model(x), y)
loss.backward()

# 🔽 加这一行！
torch.nn.utils.clip_grad_norm_(
  model.parameters(),
  max_norm=1.0 # 阈值，常用1.0
)

optimizer.step()

✅ 什么时候用？

  • 训练RNN/LSTM时（标配）
  • 训练Transformer/大模型时
  • 出现NaN时（防梯度爆炸）
  • 梯度不稳定时

⚠️ 注意

梯度裁剪只是"保险"，如果总出现梯度爆炸，说明学习率太大或者模型结构有问题，应该先调lr，而不是依赖梯度裁剪。

常见坑Top榜

新手训练模型最容易犯的错误

1️⃣ 忘记zero_grad()

梯度累积，模型更新错误。每次迭代开头必须清零！

2️⃣ 忘记model.eval()/train()

验证时Dropout/BN还在训练模式，结果随机不准。

3️⃣ 训练/测试预处理不一致

训练用了Normalize测试忘了用，或者验证集做了数据增强。

4️⃣ 数据泄露

验证集信息泄露到训练中，虚高分数上线就崩。

5️⃣ label类型错误

CrossEntropy需要label是long类型，不是one-hot，不是float。

6️⃣ 没把数据/模型转到GPU

model.to(device)和x.to(device)都要做，device要统一。

💀 终极bug：形状不匹配但没报错

比如预测和标签形状对不上但广播了，loss能算但结果完全错。建议：经常打印logits.shape和y.shape检查！

更多常见bug和解决方案

那些让你debug到怀疑人生的小问题

🐛 CUDA error: device-side assert triggered

90%是标签越界了！比如分类有10类，label里出现了10（应该是0-9）。检查label的最大值是否超过num_classes-1。

🐛 显存不足 CUDA out of memory

减小batch size、减小模型大小、用gradient_checkpointing、用混合精度训练(amp)、推理用torch.no_grad()、不要把不需要的tensor存在GPU上。

🐛 训练完验证/测试结果差

检查有没有model.eval()、有没有加载best checkpoint而不是last epoch、测试预处理和训练一致吗？有没有在训练集上测试（作弊）？

🐛 训练速度很慢

DataLoader的num_workers设为CPU核心数、pin_memory=True、用GPU训练、不要在训练循环中做.item()太多次、用混合精度。

混合精度训练 (AMP)

用FP16加速训练，节省显存，几乎不损失精度

✅ AMP的好处

  • 训练速度提升30%-50%
  • 显存占用减少约40%
  • 可以用更大的batch size
  • 现在GPU（Turing/Ampere架构）原生支持
  • PyTorch用torch.cuda.amp几行代码就搞定

🔧 代码模板

scaler = torch.cuda.amp.GradScaler()

for x, y in loader:
  optimizer.zero_grad()
  with torch.cuda.amp.autocast():
    loss = criterion(model(x), y)
  scaler.scale(loss).backward()
  scaler.step(optimizer)
  scaler.update()

💡 注意

AMP在某些情况下可能导致NaN（精度问题），如果出现NaN，先关掉AMP看是不是AMP引起的。GradScaler会自动处理梯度缩放来避免fp16溢出。

训练好模型的标准

怎么知道模型训好了？

✅ 标准1：能过拟合小数据 Sanity Check通过：在小数据集上loss能降到很低，准确率接近100%，说明模型和代码没问题。
✅ 标准2：训练和验证曲线收敛且接近 train loss和val loss都下降到一个稳定值，两者gap不大。没有明显过拟合（val loss上升）。
✅ 标准3：验证集指标达到期望 验证集准确率/loss达到你预期的目标（或比baseline好）。不是追求100%，要满足业务需求。
✅ 标准4：测试集泛化良好 在从未见过的test集上评估，结果和val集差不多（差距<2-3%）。如果差很多，说明val集可能过拟合了或者数据分布不对。

实践经验：老司机的建议

这些经验能帮你少走很多弯路

1. 从简单开始，逐步迭代

先跑通一个最简单的baseline，哪怕准确率很低。不要一上来就堆各种tricks。先有结果，再优化。

2. 做Sanity Check！

永远先在小数据集上过拟合，确认代码没问题再全量训练。这一个小步骤能节省你无数时间。

3. 固定随机种子

torch.manual_seed(42)、np.random.seed(42)、random.seed(42)——固定随机种子让结果可复现，不然改进了也不知道是不是随机因素。

4. 记录实验

每次实验记录用了什么超参数、得到什么结果，不要凭记忆。用Excel、txt或者WandB。不记录的话你会反复试同样的参数。

5. 先看数据再看模型

出问题先看数据对不对、标签对不对、可视化几个样本。90%的问题其实是数据问题，不是模型问题。

固定随机种子模板

def set_seed(seed=42):
  random.seed(seed)
  np.random.seed(seed)
  torch.manual_seed(seed)
  torch.cuda.manual_seed(seed)
  torch.cuda.manual_seed_all(seed)
  torch.backends.cudnn.deterministic = True
  torch.backends.cudnn.benchmark = False

set_seed(42) # 训练开始前调用

⚠️ 注意

完全可复现会牺牲一点速度（cudnn.benchmark=False）。做对比实验时需要固定，最终训练可以不用固定追求速度。

训练DL模型的完整方法论

📋 完整流程

数据准备→选模型→选loss/优化器→设超参数→训练循环→验证监控→诊断问题→调参迭代。先做Sanity Check！

🔍 曲线诊断

loss不动→lr/模型/数据bug；过拟合→加数据/正则/早停；收敛慢→调大lr/检查初始化/BN/残差；NaN→降lr/梯度裁剪/检查数据。

🔧 调参优先级

学习率 > batch size > 网络大小 > 优化器 > 正则化。一次只调一个参数。默认AdamW+CosineAnnealing。

⚠️ 常见坑

忘记zero_grad()、忘记model.eval()、数据泄露、标签类型错误、设备不一致。用小数据集做Sanity Check能避免90%的坑。
