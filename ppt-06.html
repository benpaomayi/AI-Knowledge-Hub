机器学习界的名言

一句话道尽数据质量的重要性

"Garbage In, Garbage Out"
—— 计算机科学经典格言
（垃圾进，垃圾出）

这句话的意思是：如果你喂给模型的数据是垃圾，那么模型输出的结果也必然是垃圾。

无论你的算法多么高级、模型多么复杂，如果输入数据质量差，结果一定不会好。这就是为什么数据预处理如此重要。

💀 真实案例

在Kaggle竞赛中，很多冠军团队的模型并不复杂，但他们在特征工程和数据预处理上花了大量时间——往往一个好的特征，比调参半天更能提升性能。

为什么数据预处理如此重要？

因为真实世界的数据——很脏

❓

缺失值

用户没填年龄、传感器偶尔失灵、数据传输丢失……导致某些字段是空的。模型看到空值就懵了。

⚠️

异常值

年龄写了200岁、收入填了-5000、一个人身高3米……这些离群点会严重干扰模型学习。

📝

非数字

性别是"男/女"、城市是"北京/上海"、颜色是"红/绿/蓝"……模型只认数字，不认文字！

🔄

重复数据

同一条记录被存了多次、爬虫抓了重复页面……重复数据会导致模型"偏听偏信"。

📏

量纲不一

年龄0-100，收入0-1000000，房子面积0-500……数值范围差异巨大，距离模型会被大数值主导。

🔊

噪声数据

测量误差、录入错误、随机波动……噪声会让模型学到错误的规律。

一、数据清洗：缺失值处理

拿到数据第一件事：检查有没有空值

# Python中检查缺失值 import pandas as pd df = pd.read_csv('data.csv') # 查看每列有多少缺失值 print(df.isnull().sum()) # 查看缺失值比例 print(df.isnull().sum() / len(df))

缺失值是最常见的数据问题。在处理之前，首先要搞清楚：为什么会缺失？缺失的原因不同，处理方式也不同。

🤔 先思考：缺失是随机的吗？

如果缺失值的出现有规律（比如低收入人群不愿填写收入），直接删除可能会引入偏差。需要先分析缺失机制。

为什么会有缺失值？

缺失值的来源多种多样，先理解原因再处理

👤

主观原因：用户未填写

问卷调查中，用户觉得某些问题涉及隐私（收入、年龄），或者觉得麻烦，就跳过了。

非随机缺失

📡

客观原因：设备故障

传感器偶尔断电、网络传输中断、服务器宕机……导致某段时间的数据没有被记录下来。

随机缺失

🚫

设计原因：无法获取

比如儿童没有收入、未婚者没有配偶信息……这些"缺失"本身就是有意义的信息。

有意义缺失

💡 经验法则

缺失比例 < 5%：可以考虑删除或填充；缺失比例 5%-20%：需要谨慎填充；缺失比例 > 50%：这一列基本可以考虑删掉了（除非缺失本身有预测价值）。

缺失值处理方法：删除法

最简单的方法——但不要滥用

🗑️ 删除行（删样本）

如果某一行有缺失值，就把这一行整个删掉。

  • 优点：简单直接
  • 缺点：丢失数据，可能丢失重要信息
  • 适用：缺失样本很少（<5%）、缺失是随机的

🔪 删除列（删特征）

如果某一列缺失太多，就把整列删掉。

  • 优点：避免引入噪声
  • 缺点：可能丢弃有用特征
  • 适用：某列缺失率很高（>50%）
# Pandas中删除缺失值 df.dropna() # 删除任何含缺失值的行 df.dropna(axis=1) # 删除任何含缺失值的列 df.dropna(thresh=5) # 保留至少有5个非空值的行

⚠️ 删除法的风险

如果缺失不是随机的（比如高收入人群都不愿填收入），删除这些样本会让你的数据集产生严重偏差，模型学到的规律是错的！

缺失值填充：高级方法

更智能的填充——用模型预测缺失值

🤖 模型预测填充

把缺失的列当作预测目标，用其他列作为特征，训练一个模型来预测缺失值。

  • KNN填充：用最相似的K个样本的值填充
  • 随机森林填充：用集成学习预测
  • 迭代填充（MICE）：多轮迭代逐步填充

🏷️ 特殊值填充

把缺失值当作一种特殊的"类别"来对待。

  • 类别型：填"未知"（Unknown）
  • 数值型：填0、-1、或一个超出正常范围的数
  • 让模型自己学习缺失值的含义

⚠️ 填充的黄金法则

永远只用训练集的统计量来填充测试集！

比如计算均值填充时，均值必须从训练集算，然后把这个均值应用到测试集。绝对不能先合并数据再计算填充值——这会造成"数据泄露"，让测试集的信息"泄露"到训练过程中，评估结果不可靠！

二、异常值检测与处理

那些"不合群"的数据点，需要特别关注

处理完缺失值，下一个问题是：数据中有没有"离谱"的值？

⚠️ 异常值（Outlier）的危害

异常值会：① 扭曲统计量（均值、方差）；② 影响模型参数学习（特别是线性模型、SVM等）；③ 导致模型过拟合到异常点上；④ 让评估指标失真。

💡 但先别急着删！

异常值不一定都是"错误"。有时候异常值恰恰是最有价值的信息——比如信用卡欺诈检测中，欺诈交易本身就是"异常值"，正是我们要找的目标！所以先分析异常值产生的原因，再决定怎么处理。

什么是异常值？

离群点——与其他观测值显著不同的数据点

想象一下，你在统计公司员工的年龄：

25, 28, 30, 32, 35, 38, 40, 42, 45, 200

大部分年龄在25-45之间，突然出现一个"200岁"——这显然是一个异常值（可能是录入错误，多打了个0）。

再看这组收入数据：

5k, 6k, 7k, 8k, 10k, 12k, 15k, 100k

🤔 这是异常值吗？

不一定。如果这是CEO的工资，那它虽然"离群"但却是真实的。这时候不能随便删，而要根据具体业务场景判断。

异常值检测方法1：IQR四分位距法

最常用、最鲁棒的统计方法——1.5倍IQR规则

$$\displaystyle IQR = Q3 - Q1 \ 下界 = Q1 - 1.5 \times IQR \ 上界 = Q3 + 1.5 \times IQR$$ 其中Q1是第25百分位数（下四分位数），Q3是第75百分位数（上四分位数）。超出[下界, 上界]范围的点视为异常值。

四分位数怎么理解？

  • 把数据从小到大排好队，分成四等份
  • Q1：排在25%位置的数（比它小的占25%）
  • Q2：中位数（50%位置）
  • Q3：排在75%位置的数（比它小的占75%）
  • IQR：中间50%数据的"宽度"
# 用IQR方法检测异常值 Q1 = df['age'].quantile(0.25) Q3 = df['age'].quantile(0.75) IQR = Q3 - Q1 lower = Q1 - 1.5 * IQR upper = Q3 + 1.5 * IQR outliers = df[(df['age'] < lower) | (df['age'] > upper)]

异常值检测方法2：3σ原则

基于正态分布的方法——三个标准差之外

若数据近似服从正态分布 N(μ, σ²)
则99.7%的数据落在 [μ - 3σ, μ + 3σ] 范围内
超出此范围的点（概率<0.3%）可视为异常值 其中μ是均值，σ是标准差。这个方法在数据近似正态分布时效果好，但对非正态分布和极端异常值本身很敏感。

3σ原则

• 基于均值和标准差
• 要求数据近似正态分布
• 异常值会扭曲均值和σ
• 不如IQR鲁棒
• 理论上覆盖99.7%数据

VS

IQR方法

• 基于百分位数
• 不要求特定分布
• 对异常值不敏感（鲁棒）
• 实际中更常用
• 基于经验规则

✅ 推荐选择

如果不确定数据分布，优先用IQR方法，它更稳健，不依赖分布假设。3σ原则在明确知道数据近似正态时使用。

异常值处理方法

检测到异常值之后，怎么办？

1

直接删除

如果确定是录入错误、测量错误，而且数量很少，直接删掉这些行。简单粗暴但有效。
df = df[(df['age'] >= lower) & (df['age'] <= upper)]

2

截断/盖帽（Capping/Winsorize）

不删除，而是把超出边界的值改成边界值。比如年龄200改成上界（比如60岁），收入超过100k的都记为100k。保留样本量，又减少极端值影响。

3

视为缺失值

把异常值当作空值处理，然后用缺失值填充方法（均值/中位数/模型预测）来填充。适合异常值较多、删除太可惜的情况。

4

分箱（Binning）

把连续值变成离散区间。比如年龄分成"18-25""26-35""36-50""50+"，异常值自然被归入"50+"这一箱，影响被削弱。

三、重复数据处理

去重——看似简单，但很容易被忽略

重复数据指的是完全相同（或大部分相同）的记录出现了多次。常见原因：

  • 数据合并时多表join产生重复
  • 爬虫重复抓取同一页面
  • 用户重复提交表单
  • 数据库没有去重约束

⚠️ 重复数据的危害

重复数据会导致：① 某些样本被模型"看到"多次，相当于增加了权重，导致偏倚；② 浪费计算资源；③ 评估时测试集如果有重复，准确率会虚高。

# Pandas检测和去除重复值 print(df.duplicated().sum()) # 查看有多少重复行 df = df.drop_duplicates() # 删除完全重复的行 df = df.drop_duplicates(subset=['user_id']) # 按特定列去重

💡 提示

去重要谨慎！有些"重复"可能不是真的重复——比如同一个用户多次购买记录，虽然user_id相同，但每条记录都是独立的购买行为，不该去重。

四、特征编码

把非数字变成数字——模型只认数字！

数据清洗完了，但还有一个大问题：很多特征是文字/类别，不是数字。

比如：

  • 性别："男""女"→ 模型不懂"男""女"是什么意思
  • 城市："北京""上海""广州"→ 文字无法做数学运算
  • 尺码："S""M""L""XL"→ 需要转换成数字
  • 颜色："红""绿""蓝"→ 怎么表示？

❌ 错误做法：直接给类别编号

北京=1, 上海=2, 广州=3, 深圳=4 ...

这样做会引入不存在的序数关系！模型会误以为"深圳(4) > 广州(3) > 上海(2) > 北京(1)"，但城市之间根本没有大小关系，这会严重干扰模型学习。

✅ 正确做法：根据类别是否有序，选择合适的编码方式

有序类别 → Label Encoding（标签编码）；无序类别 → One-Hot Encoding（独热编码）

Label Encoding 标签编码

适用于有序类别——有大小/顺序关系

👕 例子：衣服尺码

尺码 S < M < L < XL 是有明确顺序关系的，适合用标签编码：

原始值编码后
S0
M1
L2
XL3

适用场景：

  • 学历：小学<初中<高中<大学<硕士<博士
  • 评分：差<中<良<优
  • 等级：Bronze < Silver < Gold < Platinum
  • 年龄段：儿童<青少年<中年<老年
# Scikit-learn标签编码 from sklearn.preprocessing import LabelEncoder le = LabelEncoder() df['size_encoded'] = le.fit_transform(df['size']) # S→0, M→1, L→2, XL→3

⚠️ 不要乱用到无序类别！

如果给"红/绿/蓝"编号0/1/2，模型会认为"蓝(2) > 绿(1) > 红(0)"，但颜色之间没有大小关系！

适用于无序类别——没有大小顺序关系

🎨 例子：颜色

  • 性别：男/女/其他

  • 星期几：周一到周日

One-Hot编码注意事项：虚拟变量陷阱

多重共线性问题——去掉一列更健康

仔细观察独热编码的结果：

原始值颜色_红颜色_绿颜色_蓝问题
红100知道任意两列
就能推出第三列！
绿010
蓝001

🎯 虚拟变量陷阱（Dummy Variable Trap）

如果一个特征有N个类别，独热编码会产生N列。这N列之间存在完全多重共线性（可以用其他列线性表示某一列），这会导致线性模型（如线性回归、逻辑回归）的系数估计不稳定。

✅ 解决方案：丢弃一列

N个类别只需要N-1列就够了！被去掉的那一列作为"基准类别"。比如颜色红/绿/蓝，只保留"绿"和"蓝"两列：(0,0)就代表红。
代码里加一个参数就行：pd.get_dummies(df, columns=['color'], drop_first=True)

五、数据集划分

训练集 vs 测试集——为什么要分？怎么分？

数据编码好了，接下来要做一个非常重要的决定：把数据分成两部分。

📚 训练集（Training Set）

• 占大部分数据（70%-80%）
• 用来训练模型、调参数
• 模型的"课本"
• 模型在这上面学习规律

VS

• 占小部分数据（20%-30%）
• 绝对不能用来训练！
• 模型的"期末考试"
• 评估模型泛化能力

为什么要划分数据集？

核心目的：评估泛化能力，防止过拟合

🏫 类比：学生考试

想象一下：

  • 训练集 = 平时做的练习题
  • 测试集 = 期末考试题
  • 如果考试题目和练习题完全一样，学生背答案就能考满分——但他真的学会了吗？
  • 只有考没见过的新题，才能检验学生是否真正理解了知识

💀 如果不划分会怎样？

模型可以把所有训练数据都"背下来"（过拟合），在训练集上准确率100%，但遇到新数据一塌糊涂。你还以为模型很好，上线后发现根本不能用。

🎯 核心概念：泛化能力

机器学习的目标不是在训练数据上表现好，而是在从未见过的新数据上也能表现好——这就是泛化能力。

测试集模拟的就是"未来的新数据"，通过测试集上的表现，我们才能客观评估模型的真实能力。

测试集必须"锁起来"，只能用一次！

⚠️ 数据泄露

如果测试集的信息在训练时被模型看到了（比如先算全局均值再划分），就像考前泄题——考试成绩毫无意义。

📌 进阶：验证集（Validation Set）

当你需要反复调参、选模型时，可以把训练集再分成训练集和验证集（比如训练70% : 验证10% : 测试20%）。验证集用于调参，测试集只在最终评估时用一次。更高级的做法是交叉验证（Cross-Validation），以后会讲。

  • shuffle=True：划分前先打乱数据，避免数据顺序造成的偏差
  • random_state：设置随机种子，保证每次划分结果一样，方便复现
  • stratify=y：分类任务中，保持训练集和测试集的类别比例一致

六、特征缩放 Feature Scaling

把所有特征拉到同一尺度——为什么这很重要？

假设你有一个房价预测模型，两个特征：

  • 房间数量：1 ~ 10 之间
  • 房屋面积：50 ~ 500 平方英尺（100~1000平方米）

🤔 问题来了

面积的数值范围是房间数的几十倍。当模型计算距离或梯度时，面积这个特征会"主导"结果，房间数量的影响几乎被忽略——但这不代表面积更重要，只是它的数字更大而已！

✅ 特征缩放的目标

把所有特征都缩放到相同的数值范围（比如0~1之间，或者均值0、方差1），让每个特征对结果的贡献一开始是"公平"的，模型再自己学习每个特征真正的重要性。

为什么需要特征缩放？

两大类原因：基于距离的模型 + 基于梯度的模型

📏

原因一：距离计算偏倚

KNN、K-Means、SVM（核函数）等模型依赖距离计算（如欧氏距离）：

d = √[(x₁-x₂)² + (y₁-y₂)²]

如果y是面积（几百），x是房间数（几），y的差的平方会是x的成千上万倍，x这个特征几乎不起作用。

📉

原因二：梯度下降慢

线性回归、逻辑回归、神经网络等用梯度下降优化：

特征尺度差异大时，损失函数的等高线是"扁长椭圆"，梯度下降会震荡、收敛极慢；缩放后变成"圆形"，能更快收敛到最优解。

缩放可加速训练数倍甚至数十倍

Z-score 标准化（Standardization）

最常用的缩放方法——变成均值0、标准差1

$$\displaystyle x' = (x - \mu ) / \sigma$$ 其中 μ = 特征的均值，σ = 特征的标准差。

缩放后：均值 = 0，标准差 = 1，数据围绕0上下波动，大部分值在[-3, 3]之间。
不会把数据bound到固定范围，异常值仍然存在（但影响被削弱）。

标准化的特点：

  • 处理后数据均值为0，标准差为1
  • 不限制数据范围（可正可负）
  • 对异常值相对鲁棒（不像Min-Max那样被极端值压缩）
  • 实际中最常用！
# Scikit-learn标准化 from sklearn.preprocessing import StandardScaler scaler = StandardScaler() X_train_scaled = scaler.fit_transform(X_train) X_test_scaled = scaler.transform(X_test) # fit在训练集上计算μ和σ # transform用训练集的μ/σ缩放测试集！

Min-Max 归一化（Normalization）

把数据线性缩放到[0, 1]区间

$$\displaystyle x' = (x - min) / (max - min)$$ 其中 min = 特征的最小值，max = 特征的最大值。

缩放后：所有值落在 [0, 1] 范围内，最小值变成0，最大值变成1。
数据的分布形状不变，只是被"压扁"到0-1之间。

归一化的特点：

  • 处理后数据严格落在[0, 1]之间
  • 适合需要固定范围输入的场景（如神经网络、图像像素0-255→0-1）
  • 对异常值非常敏感！
  • 如果有异常值，大部分数据会被挤压到很小的范围
# Scikit-learn归一化 from sklearn.preprocessing import MinMaxScaler scaler = MinMaxScaler() X_train_scaled = scaler.fit_transform(X_train) X_test_scaled = scaler.transform(X_test) # 也可以缩放到其他范围，比如[-1, 1] scaler = MinMaxScaler(feature_range=(-1, 1))

最重要的注意事项！

特征缩放必须在数据划分之后——只在训练集fit！

❌ 错误做法

# 先缩放整个数据集，再划分 scaler.fit(X) # ❌ 用了全部数据！ X_scaled = scaler.transform(X) X_train, X_test, ... = train_test_split(X_scaled, ...) # 测试集的信息（均值/方差）泄露到了训练过程！
VS

✅ 正确做法

# 先划分，再缩放 X_train, X_test, ... = train_test_split(X, ...) scaler.fit(X_train) # ✅ 只用训练集计算参数 X_train_scaled = scaler.transform(X_train) X_test_scaled = scaler.transform(X_test) # 测试集完全用训练集的μ/σ/min/max！

💥 为什么这很重要？——数据泄露（Data Leakage）

测试集是用来模拟"未来从未见过的数据"的。如果你在缩放时用到了测试集的统计信息（比如测试集的均值、最大最小值），就相当于"未来的信息"提前泄露给了模型。这会导致测试集上的评估结果过于乐观，但上线后性能骤降！这个原则同样适用于缺失值填充、PCA等所有预处理步骤。

哪些算法需要缩放？哪些不需要？

不是所有算法都需要缩放——树模型是个例外

需要缩放 原因 代表算法
基于距离的模型 依赖距离/相似度计算，量纲影响大 KNN、K-Means、SVM（RBF核）、DBSCAN
基于梯度下降的模型 加速收敛，避免震荡 线性回归、逻辑回归、神经网络、PCA
正则化模型 正则项对特征尺度敏感 Ridge/Lasso回归、ElasticNet
不需要缩放 原因 代表算法
基于树的模型 分裂时基于阈值比较，不关心绝对大小，只关心顺序 决策树、随机森林、GBDT、XGBoost、LightGBM
朴素贝叶斯 基于概率统计，不涉及距离/梯度 朴素贝叶斯分类器

💡 实用建议

不确定时，做缩放总比不做安全。缩放不会让树模型变差，只是不做也没关系。但如果忘了给SVM/神经网络做缩放，结果可能会非常差。Pipeline可以帮你自动化这个流程。

用Pipeline串起所有步骤

好的实践——用Pipeline防止数据泄露

from sklearn.pipeline import Pipeline from sklearn.impute import SimpleImputer from sklearn.preprocessing import StandardScaler from sklearn.linear_model import LogisticRegression # 把所有预处理+模型打包成一个管道 pipeline = Pipeline([ ('imputer', SimpleImputer(strategy='mean')), # 第一步：缺失值填充 ('scaler', StandardScaler()), # 第二步：标准化 ('classifier', LogisticRegression()) # 第三步：模型 ]) # 训练：自动按顺序执行，且fit只在训练集上 pipeline.fit(X_train, y_train) # 预测：自动应用训练集学到的参数 y_pred = pipeline.predict(X_test) print(pipeline.score(X_test, y_test))

✅ Pipeline的优势

① 流程清晰，代码整洁；② 从根本上避免数据泄露——fit永远只在训练集上调用；③ 方便交叉验证和网格搜索调参；④ 模型保存/加载更简单（一个pipeline搞定）。
