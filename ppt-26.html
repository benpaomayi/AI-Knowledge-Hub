学习率是什么？

梯度下降中每次更新参数走多大一步

$$\displaystyle w = w - η \cdot \partial L/ \partial w$$ w：模型参数    ∂L/∂w：损失函数对w的梯度（告诉我们往哪走能让loss变小）
η (eta)：学习率Learning Rate——控制这一步走多远
沿着梯度反方向走η大小的一步，更新参数。
🚀

η 太大

步子迈太大，容易越过最优点，loss震荡甚至发散，模型训练失败。

✅

η 合适

稳步向最优点前进，loss稳定下降，收敛速度快，最终效果好。

🐢

η 太小

步子太小，走得极慢，容易陷入局部最优，训练时间爆炸，可能永远到不了最优点。

学习率太大：震荡与发散

步子迈太大，容易"跨过山和大海"，就是到不了最低点

⚠️ 学习率过大的典型症状

1. Loss剧烈震荡：loss曲线上下大幅跳动，不下降甚至越来越大
2. Loss直接爆炸：loss变成NaN或者inf（参数更新太大导致数值溢出）
3. 不收敛：参数在最优点附近来回跳，永远停不下来
4. 准确率不升反降：训练过程中准确率忽高忽低，没有上升趋势

❌ 初始点
→→→ 大步 →→→
⚠️ 越过最优点
←←← 大步回来 ←←←
❌ 又越过去了
→→→ ... →→→

💡 直观比喻

蒙着眼睛下山（梯度下降），如果你每一步都跨很大（lr太大），你会直接从山谷这边冲到对面山坡，再冲回来，永远在山谷两边来回晃，就是到不了谷底。

学习率太小：收敛慢与局部最优

步子太小，走到猴年马月才能到终点？

🐢 学习率过小的典型症状

1. Loss下降极慢：每个epoch loss只降一点点，训练很多轮也没收敛
2. 训练时间爆炸：别人5个epoch训完，你50个epoch还没收敛
3. 容易陷入局部最优：步子太小，遇到一个小坑就出不来了，看不到全局最优
4. 梯度消失问题更严重：深层网络中梯度本来就小，乘以很小的lr几乎不更新

⏳

收敛速度问题

lr小10倍，训练时间可能就多10倍。在算力宝贵的今天，lr太小=浪费钱和时间。

🏔️

局部最优陷阱

高维损失 Landscape 有很多局部极小值。lr太小会卡在第一个遇到的小坑里，看不到更低的全局最优。适当大lr反而能"冲"出局部最优。

💡 直观比喻

下山时每次只挪1厘米，虽然方向没错，但你要走到什么时候？而且路上随便一个小土坑你都爬不出来。

学习率合适值范围

不同优化器有不同的"舒适区"

优化器 常见学习率范围 默认/推荐值 说明
SGD 0.1 ~ 0.001 0.1 或 0.01 SGD通常需要较大lr，配合momentum效果更好
SGD + Momentum 0.1 ~ 0.001 0.01 ~ 0.1 有动量时可以稍大，冲过局部最优能力强
Adam / AdamW 0.001 ~ 0.00001 1e-3 (0.001) 自适应学习率，默认1e-3对大部分问题就很好用
RMSprop 0.001 ~ 0.0001 1e-3 和Adam类似自适应方法，默认1e-3
微调（Fine-tune） 1e-4 ~ 1e-5 1e-4 ~ 1e-5 预训练模型微调要用更小lr，不要破坏预训练权重

🎯 新手快速上手建议

用 Adam + lr=1e-3 作为起点，这是最稳妥的默认配置，90%的问题都能先跑起来。等有经验了再根据任务精调。

LR Finder：学习率查找工具

不用瞎猜！科学找到最优学习率的方法

1️⃣ 从很小lr开始
如1e-7
→
2️⃣ 每个batch线性/指数增加lr
→
3️⃣ 记录每个lr对应的loss
→
4️⃣ 选loss下降最快处的lr

📊 LR Finder原理

训练几百个step，lr从1e-7指数增长到10，记录每个lr下的loss。画出lr-loss曲线：

  • lr太小→loss不动（太小学不到东西）
  • lr合适→loss快速下降（甜蜜区）
  • lr太大→loss开始上升（开始震荡发散）

选loss下降最快、还没开始上升那个点的lr，通常是最优lr的1/10或最小值点。

💻 PyTorch Lightning中

PyTorch Lightning内置了Trainer(lr_find=True)，自动帮你做LR Finder，非常方便。

纯PyTorch可以用torch-lr-finder库，几行代码搞定。

pip install torch-lr-finder

学习率预热 Warmup

训练刚开始不要直接用大lr，先"热身"几步

⚠️ 为什么需要Warmup？

训练刚开始时，参数是随机初始化的，梯度可能非常大、不稳定。如果一上来就用大lr，很容易把参数"冲飞"，导致loss直接爆炸（NaN）。

解决方案：Warmup——训练前几步从很小的lr线性/非线性增加到目标lr，等网络稳定了再用正常lr训练。

🔥 Warmup阶段
lr从0线性增加到base_lr
→
🚀 正常训练阶段
用base_lr + scheduler衰减
🟢

Warmup步数

通常是总步数的5%-10%，比如训练10000步，warmup 500-1000步即可。

📈

Transformer必备

训练大模型/Transformer时Warmup几乎是标配！原始Transformer论文就用了Warmup。

🎯

小数据集可选

小数据集小模型不warmup也可能能训，但加了更稳，何乐而不为？

为什么需要学习率调度？

一个lr训到底不是最优——训练过程中lr应该动态调整

💡 核心直觉

训练前期：参数离最优点很远→需要较大lr快速前进
训练后期：参数已经接近最优点→需要较小lr精细调整，不然会在最低点附近震荡

就像开车：高速上开快，到目的地附近要减速找车位。从始至终一个速度开是不合理的。

📉

更好收敛

lr衰减让模型在训练后期能稳定收敛到更小的最优点，最终loss更低、准确率更高。

🏔️

跳出局部最优

周期性lr（如CosineAnnealing+重启）能帮助模型"冲"出局部最优，找到更好的全局最优点。

⚡

更快训练

OneCycle等策略先用大lr快速前进后用小lr收尾，实现"超级收敛"，训练更快效果更好。

StepLR：按步长衰减

最简单、最常用的lr调度策略

$$\displaystyle lr = base_lr \times gamma^{epoch // step_size}$$ 每经过 step_size 个epoch，lr乘以gamma。
比如step_size=30, gamma=0.1：每30个epoch lr降为原来的1/10。
from torch.optim import lr_scheduler

optimizer = optim.Adam(model.parameters(), lr=1e-3)

# 每30个epoch lr乘0.1
scheduler = lr_scheduler.StepLR(optimizer, step_size=30, gamma=0.1)

for epoch in range(epochs):
    train(...)
    scheduler.step() # 每个epoch结束调用一次

✅ 优点

简单直观、好理解、容易实现、是很多论文的baseline配置。

⚠️ 缺点

阶跃式衰减比较粗暴，需要手动选step_size和gamma，可能在衰减点lr突然变化影响训练。

MultiStepLR：多节点衰减

在指定的epoch列表点衰减，更灵活

在milestones指定的epoch处乘以gamma 比如milestones=[30, 60, 80], gamma=0.1：
epoch 0-29: lr = base_lr
epoch 30-59: lr = base_lr × 0.1
epoch 60-79: lr = base_lr × 0.01
epoch 80+: lr = base_lr × 0.001
scheduler = lr_scheduler.MultiStepLR(
    optimizer,
    milestones=[30, 60, 80], # 在这些epoch点衰减
    gamma=0.1
)

💡 使用场景

当你大概知道训练过程会在什么时候"平台期"（loss不下降了），就在那个点衰减lr，让模型继续下降。比固定StepLR更灵活，是很多竞赛选手的常用选择。

ExponentialLR：指数衰减

每个epoch都乘以gamma，平滑指数衰减

$$\displaystyle lr = base_lr \times gamma^{epoch}$$ 每个epoch lr都平滑衰减，gamma通常取0.95~0.99之间（比较接近1，衰减慢）。
scheduler = lr_scheduler.ExponentialLR(optimizer, gamma=0.95)

📊 指数衰减特点

• 平滑连续衰减，没有阶跃点
• 衰减速度由gamma控制：gamma=0.95衰减适中，gamma越接近1衰减越慢
• 缺点是训练后期lr会变得非常非常小，可能提前停止学习

CosineAnnealingLR：余弦退火

平滑的余弦式衰减，可能是当前最好用的scheduler之一

$$\displaystyle lr = min_lr + ½(base_lr - min_lr)(1 + cos(epoch \cdot \pi /T_max))$$ lr按照余弦曲线从base_lr平滑下降到min_lr（接近0），T_max是半个周期（通常设为总epoch数）。
下降过程先慢后快再慢，非常平滑自然。
scheduler = lr_scheduler.CosineAnnealingLR(
    optimizer,
    T_max=epochs, # 通常设为总训练epoch数
    eta_min=1e-6 # 最小lr
)

✅ 为什么Cosine这么受欢迎？

• 衰减平滑，没有突变，训练过程稳定
• 不需要手动调milestones等参数（只需要T_max）
• 在很多任务上效果优于StepLR，是当前Kaggle竞赛和论文的热门选择
• 配合重启（SGDR）效果更佳！

CosineAnnealingWarmRestarts：带重启的余弦退火

SGDR——周期性把lr调大，帮助跳出局部最优

🔥 核心思想

不是一直lr降到底，而是余弦下降到min_lr后，突然把lr"重启"回一个较大值，然后再余弦下降，重复这个周期。

每次lr突然变大，相当于给模型一个"动力"，帮助它"冲"出当前的局部最优，去探索loss landscape中可能更好的区域。

scheduler = lr_scheduler.CosineAnnealingWarmRestarts(
    optimizer,
    T_0=10, # 第一个周期长度
    T_mult=2, # 每次重启后周期长度乘2（越来越长）
    eta_min=1e-6
)
🔄

周期重启

大lr帮助跳出局部最优，小lr收敛，周期性重复——既训得深又不会卡住。

📈

效果通常更好

SGD+CosineRestart是很多视觉任务的SOTA配置，比固定lr效果明显提升。

🧬

类似模拟退火

思想来自模拟退火算法：前期"高温"（大lr）探索空间，后期"低温"（小lr）稳定收敛。

ReduceLROnPlateau：自适应衰减

指标不下降了再衰减，不用手动猜epoch数

🤖 ReduceLROnPlateau的聪明之处

它不按固定epoch衰减，而是监控某个指标（如验证集loss或准确率），如果连续patience个epoch指标没有改善，就自动把lr乘以factor。

scheduler = lr_scheduler.ReduceLROnPlateau(
    optimizer,
    mode='min', # min表示监控指标要下降（如val_loss）
    factor=0.1, # 衰减因子，lr乘0.1
    patience=5, # 5个epoch没改善就衰减
    verbose=True
)

for epoch in range(epochs):
    train(...)
    val_loss = validate(...)
    scheduler.step(val_loss) # 注意：要传入监控的指标值！

💡 适用场景

如果你不知道训练多少轮会收敛，用ReduceLROnPlateau最省心——它会"等"模型学不动了再降lr。

OneCycleLR：单周期超级收敛

Leslie Smith提出的"超级收敛"策略，训练更快效果更好

📈 上升阶段
从max_lr/div_factor线性增到max_lr
→
📉 下降阶段
从max_lr降到max_lr/1e4甚至更低
scheduler = lr_scheduler.OneCycleLR(
    optimizer,
    max_lr=1e-3, # 最大学习率（用LR Finder找）
    epochs=epochs,
    steps_per_epoch=len(train_loader),
    pct_start=0.3, # 30%时间用于上升，70%用于下降
    div_factor=25, # 初始lr = max_lr / 25
    final_div_factor=1e4 # 最终lr = max_lr / 1e4
)

⚠️ 注意OneCycleLR的调用位置

OneCycleLR是每个batch step一次（不是每个epoch）！scheduler.step()要放在batch循环里面，不是epoch结束后。

🏆 OneCycleLR的惊人效果

用对了OneCycleLR，训练速度可以快2-3倍，最终准确率可能还更高！fast.ai课程非常推荐这个策略，是实战中的大杀器。

差分学习率 Differential LR

不同层用不同学习率——微调预训练模型的关键技巧

🎯 为什么需要差分学习率？

用预训练模型做微调时：
• 底层（靠近输入）：学到的是通用特征（边缘、纹理、颜色），已经很好了，用小lr不要破坏
• 顶层（靠近输出）：需要适应新任务，用大lr从头学
所有层用同一个lr不科学——要么底层训坏了，要么顶层学太慢。

# 给不同层设置不同学习率
optimizer = optim.Adam([
    {'params': model.base.parameters(), 'lr': 1e-5}, # 底层：小lr
    {'params': model.middle.parameters(), 'lr': 1e-4},
    {'params': model.head.parameters(), 'lr': 1e-3}, # 顶层：大lr
], lr=1e-4) # 默认lr

✅ 这是微调的标配技巧

迁移学习/微调时几乎必用差分学习率。fast.ai的Ultralearner就是用的逐层递减lr的策略。

Batch Size与Learning Rate的关系

线性缩放规则：bs翻倍lr也翻倍

$$\displaystyle Linear Scaling Rule: 当batch size \times k时，lr也 \times k$$ 这是经验法则（来自Google论文）：batch size越大，每个step梯度越稳定（噪声小），可以用更大lr。
比如bs=64时lr=0.1，bs=256（×4）时lr可以用0.4，bs=512（×8）时lr用0.8。
Batch Size 建议LR（SGD为例） 说明
32 0.01 ~ 0.03 小batch梯度噪声大，lr不能太大
64 0.05 ~ 0.1 (基线) 常见baseline配置
128 0.1 ~ 0.2 bs×2 → lr×2
256 0.2 ~ 0.4 bs×4 → lr×4
512 0.4 ~ 0.8 bs×8 → lr×8

⚠️ 注意是参考，不是真理

线性缩放是经验法则，不是绝对真理！大batch训练还需要配合Warmup才稳定，而且实际使用时还是要验证效果，不要盲信。Adam对lr没那么敏感，缩放幅度可以小一点。

学习率与Batch Size的权衡

大batch好还是小batch好？这是个问题

🔵 大Batch Size

  • 梯度更稳定、估计更准确
  • 可以用更大lr，训练步数更少
  • GPU并行效率高，训练快
  • 但容易陷入尖锐局部最优，泛化性可能稍差
  • 需要更大显存
VS

🟢 小Batch Size

  • 梯度有噪声，反而有正则化效果
  • 有助于跳出局部最优，泛化性通常更好
  • 显存需求小，单卡就能跑
  • 但梯度噪声大，lr不能太大
  • 训练步数多，每个epoch慢

💡 实践建议

通常batch size 32~256是比较好的平衡点。别盲目追求大batch，很多实验证明小batch+适当噪声泛化更好。显存不够时梯度累积也是好办法。

PyTorch中如何用TensorBoard监控lr

可视化学习率和Loss曲线，调参更直观

from torch.utils.tensorboard import SummaryWriter

writer = SummaryWriter()

for epoch in range(epochs):
    for batch_idx, (data, target) in enumerate(train_loader):
        # ... 前向反向更新 ...

        step = epoch * len(train_loader) + batch_idx
       nbsp;writer.add_scalar('Loss/train', loss.item(), step)
        writer.add_scalar('LR', optimizer.param_groups[0]['lr'], step)

        scheduler.step() # 如果是batch级scheduler

writer.close()

# 启动命令（终端运行）：
# tensorboard --logdir=runs

把lr和loss曲线画出来，你能直观看到lr是不是太大（loss震荡）、太小（loss平）、scheduler是不是按预期工作。看图调参比瞎试高效10倍！

梯度裁剪：防止lr太大导致梯度爆炸

即使lr稍大，梯度裁剪也能救场

💥 梯度爆炸问题

深层网络中，梯度可能在反向传播中越乘越大（RNN/Transformer尤其明显），导致参数更新过大、loss变NaN。

# 在loss.backward()之后，optimizer.step()之前加这一行！
loss.backward()

# 梯度裁剪：把梯度的范数限制在max_norm以内
torch.nn.utils.clip_grad_norm(model.parameters(), max_norm=1.0)

optimizer.step()

🛡️ 梯度裁剪是免费的保险

• 几乎没有副作用，加上更安全
• 训练RNN、Transformer、大模型时强烈建议默认加上
• max_norm=1.0是常用值
• 它不会改变梯度方向，只是限制步长，防止"一步跨太远"

本集知识点总结

学习率核心要点回顾

🔑 学习率是什么

参数更新的步长η，w=w-η·∂L/∂w，是深度学习最重要的超参数，没有之一。

⚠️ 太大vs太小

太大会震荡/发散/NaN；太小收敛慢/局部最优/训练慢。合适lr通常1e-5~0.1。

🎯 默认值建议

新手从 Adam + lr=1e-3 开始，这是最稳妥的baseline，能解决90%的问题。

📊 LR Finder

科学找最优lr的方法，从极小lr开始增加，选loss下降最快处的lr。

📈 Scheduler选择

通用首选CosineAnnealing；追求极致OneCycleLR；省心用ReduceLROnPlateau；大模型记得加Warmup。

⚡ 进阶技巧

微调时用差分学习率；bs翻倍lr可翻倍（线性缩放规则）；加梯度裁剪防NaN。
